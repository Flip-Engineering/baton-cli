# Context networking: evaluating two posed orchestrator-integrated harness hypotheses

The operator posed two hypotheses about a seat harness that integrates with the baton orchestrator's shared-context plane:

1. "context as variable + baton repl native integration = native context passing?"
2. "native context navigation + context as variable + REPL = networked infinite context?"

This report evaluates both against primary sources — Recursive Language Models ([arXiv:2512.24601](https://arxiv.org/abs/2512.24601)), Continual Harness ([arXiv:2605.09998](https://arxiv.org/abs/2605.09998)), the Prime Intellect RLM blog ([primeintellect.ai/blog/rlm](https://www.primeintellect.ai/blog/rlm)), the NOOA paper ([arXiv:2607.20709](https://arxiv.org/abs/2607.20709), context and memory sections), and Context Language Models ([arXiv:2609.37725](https://arxiv.org/abs/2609.37725)) — each read in full from arXiv HTML. The baton orchestrator source at `/Users/wahargis/Development/Experiments/baton` was read at HEAD `1e050e420a99d775d3d2f943453c23535a701fd9` (2026-09-22); baton paths and line numbers resolve against that tree. The sibling reports ([nooa.md](nooa.md), [prime-agent.md](prime-agent.md), [fx.md](fx.md), [pi.md](pi.md), [deepseek-harness.md](deepseek-harness.md), [no-compaction-approaches.md](no-compaction-approaches.md), [no-compaction-harnesses.md](no-compaction-harnesses.md)) are the reference base for the lossy-boundary analysis in section 4.4.

Terms. *Context as a variable* has three published realizations: an RLM's prompt loaded as a REPL variable (paper §2.2), NOOA's live Python values in a `CodeActSession` ([nooa.md](nooa.md) §3.3), and CLM's context mirrored as a Bash-editable file synced to the live context each turn (CLM §4.1). *The baton REPL layer* is the landed REPL-1/2/3 substrate: closed content-addressed cells, named versioned bindings, and a citation grammar (docs/33; code cited in section 2.2). *Navigation* means reads directed at other sessions' contexts.

## 1. The hypotheses, restated precisely

**H1.** A seat harness whose model context is a variable (kernel value, live objects, or editable file) integrates natively with baton's REPL layer — the seat commits context state as cells and cites bindings the way baton's reports and packages already do. Claim: the composition yields *native context passing* — a seat's context is passed by reference between agents and sessions through the orchestrator: handles travel, transcripts stay local, and the receiver dereferences through the orchestrator rather than ingesting an inline body.

**H2.** Add *native context navigation* to the H1 stack: seats address and read other sessions' contexts (or their committed versions) through the orchestrator. Claim: the result is *networked infinite context* — each participant's effective context becomes unbounded because any content in the network is reachable by name.

H1 is about transfer (moving a body of context from one seat to another); H2 is about reach (every seat reading the population's committed state on demand).

## 2. Hypothesis 1: native context passing

### 2.1 What passing by reference requires

Three mechanisms: (a) an *address* — a stable name for the context (or a version of it) that outlives the emitting process; (b) a *deref path* — a read operation the receiver invokes that returns the referenced content through the orchestrator; (c) an *authority model* — the rule binding addresses to permitted readers and writers. Without (b) the transport is message passing with a compact envelope; without (c) it is an unauthenticated shared namespace.

### 2.2 What exists today

**NOOA.** Pass by reference is complete inside one process: method arguments bind as live objects, `return_result(variable)` returns values by reference from code, and tool-side variable-name references resolve from session locals (`src/nooa/strategies/codeact.py:2225-2236`). Persistence is by value at exactly one boundary: `AgentSnapshot` v2 serializes typed fields through a type allowlist and `PersistentVars` refuses live objects outright (`persistent_vars.py:36-37`). `MemoryRef` is a typed pointer into live agent state with kinds `("var", "context", "file", "todo", "memory")`, resolved at recall time by `deref` (`manager.py:488`) — the paper calls this "extending pass by reference into persistence" — and it derefs into the same agent's own state.

**Prime Agent.** The kernel namespace is per-session, durable per-variable best-effort (256 MiB ceiling; unpicklable values skipped and reported, `state_snapshot.rs`). Cross-session transfer is admission-plus-message: `rlm.spawn` returns `RlmSpawnHandle { rlm_child_id, name, session_dir, model }` once the child is admitted, and results arrive only as persisted `agent_message` entries in the session file (`core.md:33`; `agent_messaging.rs:6-9`); `agent_observe` exposes bounded read-only family status and transcript previews (`core.md:69-71`).

**fx.** Tool results above 16 KiB spill to content-addressed immutable handles (`result-{tool}-{call_sha256[:8]}-{content_sha256[:8]}.txt`, mode 0400) with a 4 KiB preview; `read_tool_result` pages them back (8 KiB default, 64 KiB max). Handles are durable references to values inside one session's own store; child subagent conversations are deliberately excluded from listing and external resume (`resume_admission.ts:103,150`).

**pi-durable.** Conversations carry ownership (`ConversationOwnership = { kind: "ownerless" } | { kind: "task"; taskId }`) and an ownership index that makes a crash-retry reuse the same child; context selection is per conversation via head markers (`context.ts`, `selectActive`). No primitive exposes one conversation's context to another.

**Continual Harness.** The paper's harness state — system prompt, sub-agents, skills, memory — is durable, structured state refined in place every F steps from trajectory evidence, with refinement information accumulating monotonically over a reset-free episode (§3.1-3.2). It is evidence that a harness's standing context can be a versioned artifact edited online from run history; Prime Agent productizes the same shape as a typed versioned harness store with review-gated refinement ([prime-agent.md](prime-agent.md) §6). The refinement loop is per-agent: neither system passes that state to another session.

**baton.** The REPL layer is the closest existing substrate for all three mechanisms, and it is landed code:

- *Cells*: content-addressed immutable JSON (`REPL_CELL_ID = /^cell:[a-f0-9]{64}$/`, `coordination-admission.mjs:106`), up to 64 MB (docs/33 §1), durably admitted with idempotent identity `context.cell:${sessionId}:${programDigest}` (`context-program.mjs:1389`), computed by the closed Bench — `outline index search slice chunk filter project sort unique join collect coverage finish` plus predicates, with `map`/`reduce` Workflow-gated (`context-program.mjs:466-541`).
- *Bindings*: `(scope, name) → cell:<sha256>`, `scope ∈ {shared, worker:<id>}`; rebind mints `bindingVersion + 1` under a CAS (`admitReplBinding`, `coordination-admission.mjs:6629-6682`); history is retained per key and every write — worker writes included — bumps a per-`(runId, scope)` fence (`coordination-ledger.mjs:3173-3185`); binding digests are hub-recomputed as `H(scope, name, bindingVersion, state, cellId)` (`coordination-ledger.mjs:423-427`). Shared-scope writes carry orchestrator authority; worker scopes accept only that worker's own writes, wrapper-bound.
- *Citations*: `repl:<scope>:<name>@<version>` (`coordination-admission.mjs:108`) resolve to the exact recorded version from history — "never 'latest'" (`coordination-store.mjs:2268-2271`) — and refuse outside the caller's own run (`repl_citation_out_of_run`, `runtime-observation.mjs:3319-3322`). `repl.cite` is an observe-class command on the embedded and MCP surfaces (`application-semantics.mjs:1625-1626`).
- *Authority*: a `ReplManifest` is a second manifest shape with a disjoint digest basis carrying `{runId, replRole}` (`context-program.mjs:319-323`); admission is the authority record and pins the admitting principal — the store comment states "only the admitting principal may compute REPL cells" (`coordination-admission.mjs:2310-2314`); a binding's scope must match the cited manifest's `replRole` and the caller's principal must match the manifest principal (`coordination-admission.mjs:6675-6682`). The semantics table records "worker manifests remain restricted to the worker own layer" and "binding version CAS remains authoritative" (`application-semantics.mjs:1241-1242`); layer policy caps a run at one `shared` layer plus one `worker:<id>` layer per fanout worker (`run-lineage.mjs:9-12`).
- *Hand-off objects*: `ContextPackage` (docs/32 §3.3) — typed immutable packages with branches (`ManifestRef | ArtifactRef | ValueRef | SchemaRef`), provenance derived from the admission ledger event, revalidation on resolve/read, and attachment scoped `run | worker:<role> | board:<board>`.
- *Notification plane*: one deployment-scope wake stream (`GET /v1/wakes`); an MCP session holds at most one upstream attachment and "a subscription is a filter, never a second connection" (`mcp-web-bridge.mjs:115-118`); frames ride a closed wake-class table, resume by ledger-seq cursor with no gap and no duplicate, and "a coordination row wakes at most once and never carries a request body" (`application-cli.mjs:2863-2884`). The attention inbox (BD3-D) is cursor-chained with mint-time coalescing and terminal-at-mint epoch marks (`coordinator.mjs:3458-3463`).

### 2.3 What is missing

For the weak reading of H1 — transfer without inline transcript bodies:

1. A **seat-side context-as-variable commit path**. No surveyed harness emits its context state as orchestrator-admissible cells at turn boundaries: NOOA snapshots into its own storage, Prime into its own session dir, CLM into its own file. baton-cli would have to make variable-to-cell commit the seat's durability boundary, so the thing passed is the same object the seat's loop reads.
2. A **context-snapshot content convention**. baton cells carry a declared media type (`application/vnd.baton.context-value+json`, `coordination-admission.mjs:110`) and schemas, but nothing declares "this cell is seat S's context as of binding version v." The branch-naming and schema convention a receiver needs is an open design item, as is commit frequency (a rebind bumps the scope fence and invalidates fence-keyed projection caches, `coordination-internals.mjs:1008-1012`).
3. A **receiver-side projection** that renders citations into model-visible context the way NOOA renders dynamic blocks or fx previews spilled results — a `repl.cite` result is a JSON receipt today; the seat harness must decide what the model sees of a cited cell.

For the strong reading — live-context dereference across processes — the absence is deliberate in every system read: baton's design rules refuse it by name ("No arbitrary-code kernel (permanent). No mutable objects. … No worker-authority shared writes", docs/33 §6) and cells are immutable with settled-only resolution (docs/33 §3.3); NOOA's deref is intra-process by construction; CLM synchronizes each context file with exactly its own server; Prime's design statement is that results travel as durable messages. Cross-process by-reference of live context has no implementation and no advocates in the primary sources.

### 2.4 Cache and failure properties of the composition

Citation hand-off keeps briefs small and the static prefix byte-stable: receivers resolve cited cells as appended content at the tail, the layout Manus states as the production rule and NOOA realizes with tail-only dynamic blocks. The failure semantics are already defined in baton: only settled, durably admitted cells resolve (docs/33 §3.3, REPL-3); post-admission artifact loss goes through §93.5 resolve-time revalidation, and live re-evaluation of a missing-artifact chain settles the cell `attention` (retryable) — named semantics, so no consumer mistakes it for a wedge. Version pinning means a reader observes the version it cited even after the author rebinds or drops the binding.

## 3. Hypothesis 2: networked infinite context

### 3.1 What navigating other sessions' contexts requires

Five mechanisms beyond H1's three: (a) *addressing that spans sessions* — names a reader can form for state it did not produce; (b) *capability grants* for cross-session reads, minted and enforced server-side; (c) *consistency across passivation* — a defined answer to what a reader sees when the target session is idle, parked, or dead; (d) *transport economics* — where dereferenced content lands in the reader's context and what it costs the reader's cache; (e) *isolation semantics* — behavior when the target is stale, rebinds mid-read, or writes hostile content.

### 3.2 What exists

- **RLM** establishes recursion over one context: sub-calls are the only published cross-context primitive, parent-to-child, prompt-in, text-out. The ablation shows the REPL-variable half alone already scales past the window (Observation 2), with sub-calls adding 10-59% on information-dense tasks.
- **CLM** is the closest published instance of networked context: "multiple context files can coexist and remain synchronized with their respective LLM servers," with subagents created and terminated by creating and deleting context files (§4.1). The Software World swarm — six agents, one per repository, over 24 hours on GPT-5.6-Sol with a 272K window — achieved 65% greater downstream speedup than a summary-compaction swarm at equal spend (§5.1.2), and the orchestrator example maintained agent scoreboards through 163 in-place edits at 6-8K live tokens (Figure 3a). CLM establishes that model-owned context scales to a swarm; it establishes no addressing, no permissions, and no cross-file dereference — each CLM owns its file, and the paper's multi-agent mechanism is coexistence.
- **fx** model-checked the routing half: `AgentRouting.tla` specifies that a session belongs to the agent its first stored input names, and a prompt sent to another agent's session is forwarded; witness configs prove the spec's mutations detectable and the generated state graphs are walked against the real runtime ([fx.md](fx.md) §11). Routing forwards requests; it reads nothing.
- **Prime** has bounded cross-session reads: `agent_observe` (family status, transcript previews) and the daemon's windowed session reads over `{session_id}.jsonl` stores (`session_store.rs:110-124`); reads are bounded, parent-scoped projections, and the spawn ledger keeps non-resident children addressable after passivation (`rlm_ledger.rs`).
- **baton** has the notification half and the bounded-read half of navigation. The wake plane (section 2.2) delivers every coordination row at most once with a ledger-seq cursor; the attention inbox chains wake reasons by cursor with coalescing; the reading half is bounded projections — swarm view, evidence search, knowledge horizons (docs/34), board reads, `repl.cite` — each byte-bounded with explicit shed markers (`view.repl.bytes`, `MAX_REPL_BINDING_ITEMS = 512` with never-silent shedding, `application.mjs:694-725`; `view.wake_replay.items = 4096`, `limits.mjs:285`).

### 3.3 What is missing

1. **Cross-session addressing.** baton citations resolve only in the caller's own run (`repl_citation_out_of_run`), and docs/33 §6 names "No cross-run bindings" a non-goal (project-persistent objects ride the knowledge graph, docs/34). Peer-to-peer addressing needs a run-scoped grant or a deployment-scoped namespace; neither exists.
2. **Capability grants for context reads.** Grants exist for board claims: `waves.send` with `claimGrant` mints one closed server-side grant before the steer is deliverable, the caller names no grantee and no permissions, and "the delivered worker fact never carries S-2 lease material" (`application.mjs:7722-7725`; `coordination-store.mjs:2190-2194`). No equivalent exists for reading another seat's REPL layer or packages; `repl.cite` is observe-class but run-scoped.
3. **A navigation operator with a declared read budget.** Every harness in the survey budgets reads (NOOA's `prefill_format` at 2,000 characters per preview; fx's 64 KiB model-visible cap with paging; Prime's 64 KiB host-side per-execution cap; baton's frame limits on views). What one dereference of another seat's context may return, and where the budget lives (orchestrator frame limit or seat-side projection), is undefined.
4. **A consistency contract for live state.** Reading a passivated seat's committed cells is well-defined — cells are immutable and replay-exact, and citations pin versions. Reading a live variable is not: Prime's kernel namespaces die with their process and revive per-variable best-effort, and NOOA's locals die with the method. The composition needs the definition "the context of a session is its committed version line," which the baton binding history already provides if the seat commits at turn boundaries.
5. **Shared live context with independent writers.** No published system lets two model-owned contexts be one addressable object: CLM's files are per-server; baton's objects are immutable with single-writer scopes. The strongest form of H2 has no implementation anywhere in the corpus.

### 3.4 A field observation: idea-population optimization as a further posture

An X post by dimenwarper (@tsuname), 2026-10-13 ([status/2109876913544298678](https://x.com/tsuname/status/2109876913544298678)), observes that "autoresearch folks are revisiting all of optimization's greatest hits: there's idea momentum, idea cross-entropy search, idea simulated annealing, etc". The tweet is anecdote; the systems are the evidence, and their published operators are real:

- **Co-Scientist** (Google, [arXiv:2502.18864](https://arxiv.org/abs/2502.18864)): a tournament evolution process over a hypothesis population — pairwise-battle Elo ranking validated against GPQA Diamond, with top-ranked hypotheses fed to the evolution agent each round. Top-k selection with winner carryover; the closest published "momentum" operator.
- **The AI Scientist** (Sakana AI, [arXiv:2408.06292](https://arxiv.org/abs/2408.06292)): iterative generate-experiment-review loops repeatable in an open-ended fashion; **AI Scientist-v2** ([arXiv:2504.08066](https://arxiv.org/abs/2504.08066)) replaces the fixed pipeline with best-first tree search over experiment trajectories under an Experiment Manager Agent — an exploration-budget operator.
- **FunSearch** (Romera-Paredes et al., Nature, December 2023): island-based evolution of programs — LLM mutation of best-of-generation prompts, sandbox evaluation, independent islands with periodic migration, weak islands reset from elites. The closest published "annealing" operator (restarts) and CEM-like top-k sampling.
- **AlphaEvolve** (DeepMind, [arXiv:2506.13131](https://arxiv.org/abs/2506.13131)): an evolutionary database of programs with `EVOLVE-BLOCK` mutation and evaluator-based selection (a 4×4 complex matrix-multiply in 48 multiplications, the first Strassen improvement in 56 years); **LLM-SR** ([arXiv:2404.18400](https://arxiv.org/abs/2404.18400)) runs the same shape over equation skeletons with fitness-weighted sampling; **GEPA** ([arXiv:2507.19457](https://arxiv.org/abs/2507.19457), cited by the NOOA and CLM papers) is the same operator family over prompt artifacts.

Two evaluations follow. (a) *Posture*: the standing artifact in these systems is a typed, scored population (hypotheses with Elo, programs with fitness) that persists outside any window, and the context a model works from at a step is a bounded read of the population's frontier. That is a posture beyond the four in [no-compaction-approaches.md](no-compaction-approaches.md) (budget the history, move the projection out, curate the standing artifact, spend the native window): ACE is its one-artifact special case, and the population form adds what the one-artifact form lacks — selection pressure over competing artifacts and explicit exploration budgets, which make the store a search state. (b) *Interaction with the hypotheses*: the operators act on a population, and in an orchestrator-integrated system the natural population is findings across seats. Both candidate stores exist — baton's knowledge layer (typed knowledge records with groundings and edges, `KNOWLEDGE_NODE_TYPES`/`KNOWLEDGE_EDGE_TYPES` at `coordination-admission.mjs:14`; `knowledge.recall` and `knowledge.horizon` reads; `knowledge.promote` under S-2 session authority; promotion across task→workflow→project horizons, docs/34) and Prime's refinement store (typed versioned entries with evidence-and-outcome-bearing events and rollback by id, [prime-agent.md](prime-agent.md) §6). The operators are the missing piece: no orchestrator today runs tournament, top-k, or island operators over its knowledge store. For H2 the observation reframes an organization question: networked context organized as navigation answers what is reachable and what a read costs; organized as optimization it answers which committed frontier survives. The two compose — ranked reads over a scored population bound the dereference budget (section 3.3, item 3) and give the commit-time loss (section 4.4) a selection-driven policy.

## 4. Load-bearing risks

### 4.1 Reference invalidation across processes

The survey's consistent rule: only content-addressed values cross a process boundary. fx's handles are immutable blobs (mode 0400); baton's cells are immutable and its citations pin versions; Prime's results are durable message entries precisely because live kernel state is best-effort; NOOA serializes live objects at no boundary except durability. Content-addressed references cannot dangle; the residual failure is artifact loss, which baton names and handles — resolve-time revalidation per §93.5, and live re-evaluation of a missing-artifact chain settling the cell `attention` (retryable) rather than wedging (docs/33 §3.3, items 8-9). Version pinning trades invalidation for staleness: a citation resolves the version recorded at cite time even after the target rebinds, so a reader needing current state cites again. "Handles never invalidate" and "handles never go stale" cannot both be claimed; the design has to pick, and baton picks replay-exactness.

### 4.2 Capability and security of cross-session reads

A dereference imports another session's content into the reader's prompt — untrusted input at the exact position CLM's safety section names: editable context becomes a channel through which injections persist across turns, with compaction summaries already observed carrying unauthorized instructions (CLM §6, citing OpenAI 2026b). A peer seat is a capable writer, which raises the stakes beyond file-backed memory tools. baton's existing posture transfers directly: branch content is "untrusted input to every reader" with ledger-derived provenance, so a package cannot carry a self-cited authority claim (docs/32 §3.3); worker-authored prose passes `boundedAttentionText` sanitization with untrusted provenance; source ingestion answers two closed codes — `context_source_oversize` (a projection fact, never a confidentiality claim) and `context_source_sensitive` (a named shape on a named line, never the matched text) (`context-program.mjs:674-679`). The missing piece is grant plumbing for reads — minted server-side, non-transferable, on the `mintMemberBoardGrant` pattern — with the dereference result delivered through the reader's own authenticated channel.

### 4.3 KV-cache economics when context is networked

Navigation results land in the navigator's context, so the network's cost is paid in the navigator's cache. Appended at the tail, dereferences preserve the cached prefix — the discipline Manus states as the production rule and NOOA realizes structurally with tail-only dynamic blocks ([no-compaction-approaches.md](no-compaction-approaches.md) §1; [nooa.md](nooa.md) §3.1). Interleaved dereferences re-prefill from the first mismatched token: CLM defines the accounting as prefix-reuse FLOPs (re-prefill of the unmatched suffix plus decode) and measures its 12-hour and 24-hour runs under it; Suffix Cache Reuse recovers reuse beyond the matching prefix and matches standard serving at 65.0% of its empirical prefix-reuse FLOPs, but most of that saving comes from reasoning-token stripping (5.3 of 7.8 reused points), and SCR is a serving-side patch, not a harness behavior. Cross-reader cache sharing requires byte-identical prefixes, which heterogeneous navigation patterns break — each reader pays for its own assembled projection. baton's cache-stability machinery (fence-keyed projection caches, deterministic canonical serialization, byte-bounded shedding) applies to views, and the harness-side rule for dereferences is the one the sibling harnesses already use: resolve at the tail, budget the projection, never silently truncate.

### 4.4 Is "infinite" achievable, or does the lossy boundary move

The sibling reports' shared finding is that every surveyed architecture contains a lossy boundary and the designs differ in where they place it ([no-compaction-approaches.md](no-compaction-approaches.md) §8; [nooa.md](nooa.md) §3.6; [no-compaction-harnesses.md](no-compaction-harnesses.md) §9). Networking moves the boundary to three places; it does not remove it:

1. **Commit time** — what each session's owner writes out. CLM's edits are lossy by model judgment, accepted as the design; NOOA commits only snapshot-serializable values; Prime's per-variable snapshots skip unpicklable values with a report. A networked context inherits the union of these losses: whatever a peer never committed is unreachable at any price.
2. **Deref time** — what a read returns. Every read in the corpus is bounded: NOOA previews, fx's 64 KiB cap with 4 KiB previews, Prime's host-side cap, baton's frame limits with typed shed markers. A networked read is a projection of the target's committed state, chosen by the same disciplines.
3. **Authority time** — what a reader may name at all. `repl_citation_out_of_run`, the worker-layer restriction on manifests, and run-scoped packages each bound the reachable set before any bytes move.

The RLM paper's own numbers bound the claim empirically: RLM(GPT-5) reaches 58.00% F1 on OOLONG-Pairs against a base-model floor below 0.1%, and 91.33% on BrowseComp-Plus-1K — strong and incomplete; median cost sits below base-model runs with high variance at the tail from long trajectories (Observation 4). The REPL-only ablation outperforms the full RLM on two tasks (+17.9% on CodeQA for Qwen3-Coder), so the variable half carries most of the value and the recursive, networked half is additive on information-dense inputs. "Infinite" holds for the addressable store — append-only logs and content-addressed cells are lossless by construction, and baton's ledger, binding history, and cell store are exactly that shape. The effective context of every participant stays a budgeted function of the three placements above; CLM's swarm shows the same in practice (6-8K live orchestrator context against a 24-hour, six-agent workload).

## 5. Verdicts

### 5.1 Hypothesis 1 — coherent composition with one named correction

**Verdict: coherent under the weak reading; a category error under the strong reading.**

- Weak reading (transfer without inline transcript bodies): coherent, and the missing substrate is exactly what baton's REPL layer provides — versioned, content-addressed bindings with principal-pinned admission and a citation grammar that no surveyed harness has across processes. What the composition yields is *native context addressing*: the seat's context variable and the orchestrator's object layer take the same shape (content-addressed, versioned, citable), and transfer becomes commit-and-cite. The passing itself remains by value at the commit point — every architecture in the corpus, including baton by explicit design rule, serializes at that boundary, so "passed by reference" is true of the address and false of the bytes. The claim is half right, and the wrong half is wrong by design consensus, not by missing engineering.
- Strong reading (live-context dereference across processes): a category error. baton refuses mutable shared objects and cross-run bindings as non-goals (docs/33 §6); NOOA's deref is intra-process; CLM's files are per-server; Prime's results travel as durable messages. No primitive exists for it, and the systems that could build one have each recorded a decision against it.

**Minimal experiment.** Build the weak reading in baton-cli: seat context-as-variable (a kernel variable or file the loop reads), committed as cells into the seat's `worker:<id>` layer at turn boundaries under a declared snapshot schema; briefs and reports carry `repl:` citations; the orchestrator promotes one committed version to `shared` by rebind. Run a two-seat task where seat B's work requires seat A's intermediate state. Measure: (a) token cost versus an inline-transcript baseline; (b) prefix-cache stability across commits; (c) replay-exactness — B's dereference returns the exact bytes A committed (binding digest match); (d) failure behavior when A rebinds mid-task (B keeps its cited version).

**Settling evidence.** Equal-or-better task success with materially lower token spend, cache-hit rates that survive the commit cadence, and citation resolution that is replay-exact across seat restarts. If commits must be frequent to stay useful and each commit invalidates receiver caches, the composition trades cache economics for addressing, and the verdict downgrades to "coherent, conditionally worth it."

### 5.2 Hypothesis 2 — coherent stack, overclaimed conclusion

**Verdict: the composition is a coherent research program; "infinite" is a category error in its strong reading.**

The stack (navigation + context-as-variable + a closed REPL) is buildable from parts that all exist: baton's addressing, fencing, authority, and wake/inbox planes; the RLM/NOOA/CLM variable half; CLM's swarm as the existence proof that model-owned context scales to many agents. The composition achieves: the *addressable* context becomes unbounded (append-only ledgers and content-addressed cells), each participant's *effective* context becomes a budgeted function of navigation, and cross-session state stops transiting as inline bodies. It does not achieve unbounded effective context: the lossy boundary moves to commit, dereference, and authority time (section 4.4), context rot applies to whatever a navigator assembles ([no-compaction-approaches.md](no-compaction-approaches.md) §6), and the RLM/CLM numbers show the assembled surface stays bounded in every working system. The five missing mechanisms in section 3.3 are the concrete gap; the two hardest are cross-session addressing with grants and the consistency contract for passivated targets.

**Minimal experiment.** Extend the H1 prototype with one navigation path: seat B dereferences a binding in seat A's `worker:<id>` layer through an orchestrator-mediated read, authorized by a server-minted, non-transferable grant on the `mintMemberBoardGrant` pattern, with a declared per-dereference read budget and the result appended at B's context tail. Run task classes where B's answer requires A's committed state, against a re-derivation baseline (B recomputes A's work).

**Settling evidence.** Navigation beats re-derivation on cost at matched accuracy for a measurable task class; stale-citation behavior is benign (B completes on the pinned version or fails typed); grant enforcement survives adversarial content in A's committed cells (injection attempts are provenance-marked and sanitized, with no privilege change in B). If navigation only pays when A commits at high frequency, or if dereference budgets make B re-derive anyway, the hypothesis reduces to H1 plus search over knowledge horizons, and the "networked" framing overstates it.

Section 3.4 adds one consideration to this verdict: if the committed cross-seat store is treated as a search state under population operators (tournament, top-k, island restarts), navigation reads become ranked reads of a frontier — which turns missing-mechanism 3 from budgeting arbitrary dereferences into budgeting ranked reads, and gives the commit-time loss a selection-driven policy.

## 6. Open questions

- What commit cadence keeps a seat's context snapshot useful without destroying receiver caches? Every rebind bumps the scope fence and invalidates fence-keyed projection caches (`coordination-internals.mjs:1008-1012`); the interaction between commit frequency and cache stability is unmeasured.
- Can CLM-style live file editing compose with baton's immutable-cell admission? The two durability models are opposed (unrestricted in-place edits versus settled, immutable, version-CAS objects); no hybrid is described in either paper or in baton.
- Where does a dereference read budget live — the orchestrator's frame-limit registry (`limits.mjs`) or the seat's projection layer — and what is the right default?
- Is cross-run navigation ever needed, or do run-scoped addressing plus knowledge promotion (docs/34) cover the cases? baton's non-goal is explicit; workload evidence for the deployment-scoped form is absent from every source read.
- No serving-side reuse primitive exists for readers with divergent assembled prefixes; SCR recovers within-request and reasoning-stripping reuse only (CLM Appendix B).
- The CLM swarm ran with coexisting files and no cross-file dereference; whether networked reads beat re-derivation is unmeasured anywhere in the corpus.
