# Compaction-free agent contexts: the published approaches, late 2026

This report surveys the approaches published as papers, official engineering blogs, and vendor documentation for operating agent contexts with little or no compaction. It complements [nooa.md](nooa.md), the anchor example: NOOA avoids compaction by budgeting the projection (bounded previews) while whole values live in the process, keeping a cache-stable three-region transcript, and reserving serialization for the durability boundary. The approaches here answer the same problem at other layers of the stack: inside the prompt (cache-first layout, fine-grained clearing, recitation), across sessions (structured note-taking, memory paging, sleep-time consolidation), outside the window entirely (playbook evolution, external memory services), or by spending the native window directly (mega-context plus prompt caching), with context rot as the standing failure mode of that last path.

Method: every load-bearing claim below links a primary source — the paper, the vendor's own blog or documentation, or the benchmark report — read 2026-10-14 to 2026-10-15. Vendor-reported numbers are labeled as such. Uncertainties are collected in section 9. Shipping-harness implementations of the same ideas are covered by [no-compaction-harnesses.md](no-compaction-harnesses.md); this report stays at the level of the published concepts.

## 1. Cache-first append-only context: Manus (July 2025)

Mechanism ([Context Engineering for AI Agents](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus), Yichao "Peak" Ji, 2025-07-18): the post names the KV-cache hit rate "the single most important metric for a production-stage AI agent." The agent loop is prefill-dominated — Manus reports an average input-to-output token ratio around 100:1 — so per-turn cost and latency are decided by what is prefilled. The pricing example given is Claude Sonnet at $0.30/MTok cached versus $3.00/MTok uncached, a 10x spread (blog-era pricing; current multipliers in section 6).

The context disciplines that follow are three: keep the prompt prefix byte-stable (a timestamp in the system prompt invalidates the cache from that token onward); make the context append-only, with deterministic serialization (unstable JSON key ordering silently breaks the cache); and mark cache breakpoints explicitly where the provider lacks automatic prefix caching.

Tools are masked, kept in the prompt. Manus's experiments found that dynamically adding or removing tools mid-task invalidates the cache at the tool-definition position and confuses the model when earlier turns reference tools no longer defined; the fix is a context-aware state machine that masks token logits at decode time (prefill modes auto/required/specified), with consistently-prefixed tool names (`browser_`, `shell_`) so a whole group can be constrained without stateful logit processors.

The file system is the designated long-term store: "unlimited in size, persistent by nature, and directly operable by the agent itself." The post's argument for keeping observations out of the window is that an agent must predict the next action from all prior state, that no one can predict which observation matters ten steps later, and that "any irreversible compression carries risk." Manus's compression is therefore always designed to be restorable: a web page's content may be dropped while the URL is kept, a document's content while its sandbox path is kept.

Attention is managed by recitation: the agent rewrites a `todo.md` at each step, pushing the global plan back into the end of the context; a typical Manus task runs about 50 tool calls, long enough for goals to drift without this. Two further disciplines: keep failed turns in the context, because erasing failure removes the evidence the model adapts from; and inject structured variation into repetitive action/observation pairs, because a uniform context few-shots the model into repeating its own pattern (the 20-resume-review example).

Evidence: the post is practitioner narrative without ablations; the 100:1 ratio and the 50-call average are Manus-reported. The restorable-compression design and the logit-masking tool gate are the load-bearing mechanisms, and both are concrete enough to reimplement.

Tradeoffs. Recitation re-sends the todo each turn, spending window space and cache writes to buy attention. The filesystem move makes every large value cross a serialization boundary (process to file to context) — precisely the boundary NOOA refuses to cross mid-session. Masking requires provider prefill support, which not every inference stack offers.

## 2. Harness-managed memory and fine-grained clearing: Anthropic (2025–2026)

Mechanism. The [effective context engineering post](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (Sep 29, 2025) frames context as a finite resource with an "attention budget" and surveys three long-horizon techniques: compaction (summarize and reinitialize), structured note-taking (the agent writes notes persisted outside the window and reads them back — NOTES.md, memory files), and sub-agent architectures (deep exploration isolated in child contexts, a 1,000–2,000-token summary returned to the lead). It also defines the just-in-time retrieval posture: agents hold lightweight identifiers (paths, queries, links) and load content on demand, as Claude Code does with `glob`/`grep` and shell over large data. The post names tool-result clearing "one of the safest lightest touch forms of compaction."

The [context-management announcement](https://www.anthropic.com/news/context-management) (Sep 29, 2025) and the current platform docs specify the mechanisms.

- **Context editing** is server-side: the API clears content from the conversation before the prompt reaches the model, and the client keeps its own full, unmodified history ([docs](https://platform.claude.com/docs/en/build-with-claude/context-editing), beta header `context-management-2025-06-27`). The `clear_tool_uses_20250919` strategy clears the oldest tool results in chronological order once a trigger threshold is exceeded, replacing each with placeholder text. Defaults, verified from the docs' configuration table: trigger 100,000 input tokens; keep 3 most-recent tool use/result pairs; `clear_at_least` none; `exclude_tools` none; `clear_tool_inputs` false — by default the tool calls stay visible and only results are cleared. Clearing invalidates cached prompt prefixes at the cleared position, which is why `clear_at_least` exists: if the strategy cannot clear the requested minimum, it is not applied.
- The `clear_thinking_20251015` strategy manages thinking blocks from earlier turns. Defaults are model-class-specific: Opus 4.5+, Sonnet 4.6+, and Haiku 5.5+ keep all prior thinking (it stays in window and cache); earlier models keep only the last turn's.
- **Memory tool** ([docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)): the tool entry `{"type": "memory_20250818", "name": "memory"}` exposes six client-side file operations (`view`, `create`, `str_replace`, `insert`, `delete`, `rename`) over a `/memories` directory whose storage the application owns. Claude checks memory before starting a task and writes findings there for later conversations; the handler must reject paths outside `/memories`.
- **Server-side compaction** is the docs' recommended primary strategy for long-running conversations ([overview](https://platform.claude.com/docs/en/build-with-claude/compaction), on-demand beta header `compact-2026-09-04`): a Claude-written summary replaces older turns, with on-demand and token-threshold variants, an option to keep recent turns word-for-word, and a background mode.
- **Client-side SDK compaction** is the third option in the same docs: the TypeScript and Ruby SDKs' `tool_runner` generates a summary and replaces the full history, with a `context_token_threshold` defaulting to 100,000 tokens. The docs document two operational caveats: server-side tool usage fields (e.g. `cache_read_input_tokens` accumulated across internal web-search calls) can make the SDK overestimate context length and trigger compaction prematurely, and a compaction triggered while a tool call is pending removes the pending call from history — Claude re-issues it after resuming if still needed.

Evidence, vendor-reported from the announcement: on an internal agentic-search evaluation, memory tool plus context editing improved performance 39% over baseline and context editing alone 29%; in a 100-turn web-search evaluation, context editing reduced token consumption 84% and let agents finish workflows that otherwise exhausted the window. No benchmark definition or harness configuration is published for either number.

Two 2026 additions extend the picture. [Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) (Nov 26, 2025) reports that compaction alone is insufficient across many windows: the Claude Agent SDK experiments needed an initializer agent (writes a JSON feature list — chosen over Markdown because models overwrite Markdown more readily — plus a progress file and `init.sh`) and a coding agent prompted to make incremental progress, commit with descriptive messages, and leave a clean state. [Claude Managed Agents](https://platform.claude.com/docs/en/managed-agents/overview) (beta header `managed-agents-2026-04-01`) moves the whole harness — loop, tools, sandbox, caching, compaction, stateful sessions — behind an API, and its [Dreams](https://platform.claude.com/docs/en/managed-agents/dreams) research preview (`dreaming-2026-04-21`) runs an asynchronous job over a memory store plus up to 100 past sessions that produces a new, reorganized store: duplicates merged, stale or contradicted entries replaced, insights surfaced; the input store is never modified.

Tradeoffs. Clearing rewrites the visible history at a threshold, so every trigger is a cache invalidation (the docs say so explicitly); the cleared content is gone from the model's view, and what "stale" means is a per-tool judgment encoded in `exclude_tools` lists. The memory tool keeps the window clean by moving state to files the model must re-read — cost shifts to retrieval correctness. Managed Agents concentrates both the harness and the memory server-side, which is the lock-in risk section 7's ecosystem debate centers on.

## 3. Memory paging and sleep-time compute: MemGPT / Letta (2023–2026)

Mechanism. MemGPT ([arXiv:2310.08560](https://arxiv.org/abs/2310.08560), 2023-10-12) introduced "virtual context management": a memory hierarchy in which the LLM's own function calls page data between an in-context main context (like RAM) and external storage (like disk), with interrupts to yield control flow. The [Letta memory model](https://www.letta.com/blog/agent-memory) (Jul 7, 2025) names the four components: a message buffer (recent turns), core memory (in-context blocks, each with label, description, value, and a character limit, editable via tools by the agent or by other agents), recall memory (the searchable conversation history on disk), and archival memory (processed knowledge in vector or graph stores, retrieved by tool call). The paging architecture moves state between tiers; whatever leaves the buffer is still queryable, which is what makes eviction restorable.

Sleep-time compute ([Letta blog](https://www.letta.com/blog/sleep-time-compute), Apr 21, 2025; [arXiv:2504.13171](https://arxiv.org/abs/2504.13171), April 2025) splits the agent in two: a primary agent that converses and calls tools, and a sleep-time agent that owns core-memory editing for both. Memory management happens asynchronously; the sleep-time agent rewrites memory blocks into "clean, concise, and detailed" form and can pre-process uploaded documents in the background — the blog emphasizes "anytime" semantics: the primary agent reads the memory whenever, without waiting. The paper's framing: reasoning over idle periods transforms "raw context" into "learned context," which reduces the reasoning the model must do at query time.

Evidence. On the paper's Stateful GSM-Symbolic and Stateful AIME (each problem split into context and question): sleep-time compute reached the same accuracy with roughly 5x less test-time compute; scaling sleep-time compute further moved accuracy up by 13% (GSM-Symbolic) and 18% (AIME) at similar test-time budgets; amortizing one sleep pass over multiple queries sharing a context cut average cost per question 2.5x. Gains concentrate on queries predictable from the context (§5.4) — the paper's own stated scope limit.

Tradeoffs. Memory-block quality now depends on a second model's judgment, run on a second budget; the original MemGPT design bundled memory management into the main loop, and the blog itself documents why that made agents slower and memories messier over time. The Letta lineage still ships eviction and recursive summarization for the buffer; the design statement is about where state lives and when it is edited, with compaction retained as the buffer's safety valve. Anthropic's Dreams (section 2) is the same consolidation pattern productized server-side in 2026.

## 4. Evolving-context playbooks: ACE (October 2025)

Mechanism. [ACE: Agentic Context Engineering](https://arxiv.org/abs/2510.04618) (Zhang et al., 2025-10-06) treats the context itself as the trainable artifact: an evolving playbook of itemized strategies maintained by a generator/reflector/curator loop. The generator executes with the current playbook; the reflector mines execution traces and natural feedback for what worked; the curator merges structured delta updates — itemized bullets with metadata such as helpful/harmful counts — appending and retiring items. The paper's diagnosis of why summarization-based loops fail is two failure modes: brevity bias (optimization pressure drops domain detail for concise summaries) and context collapse (iterative rewriting erodes specifics across generations). Incremental delta updates to a structured artifact are the fix, and ACE applies them to both offline contexts (system prompts) and online ones (agent memory), adapting without labeled supervision.

Evidence, from the paper's abstract and results: +10.6% on agent benchmarks and +8.6% on finance against strong baselines, with reduced adaptation latency and rollout cost; on the AppWorld leaderboard, an ACE-driven agent using a smaller open-source base model matched the top-ranked production agent on overall average and surpassed it on the harder test-challenge split.

Tradeoffs. A playbook grows monotonically by design; the paper argues the structure "scales with long-context models," but the pruning burden moves into the curator's heuristics rather than disappearing. ACE curates the standing context artifact; the per-session transcript problem remains orthogonal. The mechanism is the same anti-collapse move as an append-only event log — structured, itemized, addressable updates — applied one layer up, to the instructions rather than the history.

## 5. External memory systems: Mem0, Zep/Graphiti, MemOS, Cognee

Common mechanism: remove conversational state from the window entirely. A pipeline extracts durable facts from sessions into an external store (vector, graph, or hybrid), and per-turn retrieval injects only what the current query needs. What each claims to remove from the window is the raw history; what stays is a retrieval projection of it.

- **Mem0** ([arXiv:2504.19413](https://arxiv.org/abs/2504.19413), 2025-04-28): extracts, consolidates, and retrieves salient information from ongoing conversations, with a graph-based variant. On LOCOMO: 26% relative improvement in LLM-judge score over OpenAI's memory; the graph variant about 2% higher than base; 91% lower p95 latency and over 90% token-cost savings versus a full-context baseline. The paper's own numbers complicate the story: the full-context baseline — about 26,031 memory tokens of history in the window — scored highest overall (J = 72.90 ± 0.19) at a total p95 latency of 17.1s, while Mem0's variants scored lower (68.44% for the graph variant) at around 2.6s p95. The published case is therefore cost and latency at near-accuracy, on a benchmark whose entire history still fits a modern window outright. The paper also documents an externality of graph construction in Zep: searches immediately after ingestion often failed, with results improving hours later, because graph building runs multiple asynchronous LLM calls in the background.
- **Zep / Graphiti** ([arXiv:2501.13956](https://arxiv.org/abs/2501.13956), 2025-01-20): a temporally aware knowledge-graph engine that synthesizes conversation and business data while maintaining historical relationships. Reports 94.8% versus MemGPT's 93.4% on Deep Memory Retrieval, and on LongMemEval accuracy improvements up to 18.5% with 90% response-latency reduction against baseline implementations.
- **MemOS** ([arXiv:2507.03724](https://arxiv.org/abs/2507.03724), 2025-07-04): memory as a first-class, schedulable system resource. The MemCube unit encapsulates content plus metadata (provenance, versioning) across three substrates — plaintext, activation (KV-cache-resident), and parameter memory (e.g. LoRA deltas) — with policy-aware scheduling that promotes hot memories to faster tiers and transforms memories between substrates (parameter to plaintext and back). On LOCOMO the paper reports overall LLM-judge 73.31 ± 0.05 for MemOS versus 64.57 for Mem0, 41.62–42.20 for Zep, and 52.75–61.83 for OpenAI's memory, with per-query token and latency columns; it also reports TTFT reductions from KV-based memory injection. As with Mem0, the paper's own text concedes that the full-context baseline "achieves strong LLMJudge scores but suffers from prohibitively high latency." The MemOS 2.0 runtime (view-based operations, asynchronous scheduler) is documented in the [repository](https://github.com/MemTensor/MemOS); repo-documented claims beyond the paper are treated here as such.
- **Cognee** ([repository](https://github.com/topoteretes/cognee); research paper [arXiv:2505.24478](https://arxiv.org/abs/2505.24478), "Optimizing the Interface Between Knowledge Graphs and LLMs for Complex Reasoning," 2025): an open-source memory platform that turns documents, code, and conversations into a self-hosted knowledge graph plus vector search, runnable locally without an API key using small local models (GLiNER-based extraction). Its surface is `remember`/`recall` primitives plus session distillation, which curates accepted session lessons into permanent memory.

Tradeoffs, common to the family. Retrieval now decides what the model sees — the projection budget moves out of the harness into a service whose quality the harness cannot inspect mid-run. Extraction is asynchronous (Mem0's Zep observation), so freshly ingested state may not be queryable. Provenance and staleness need explicit design (MemOS's versioning metadata; Cloudflare's supersession chains in section 7). And the vendor benchmarks disagree with each other: Mem0's paper, MemOS's paper, and Zep's paper each rank the others differently on overlapping benchmarks — section 9 records this as the family's standing evidentiary problem. Cloudflare's Agent Memory post adds the structural warning that benchmark-tuned memory systems can overfit their evaluations.

## 6. Native mega-context plus prompt caching: the baseline, and what breaks first

The window side. As of October 2026 the published model specs are: GPT-5.1 at a 400,000-token context window with 128,000-token output ([OpenAI model docs](https://developers.openai.com/api/docs/models/gpt-5.1)); Claude's current models (Fable 5.1, Mythos 5.1, Opus 5.5/5/4.8/4.7/4.6, Sonnet 5.5/5/4.6, Haiku 5.5) at a 1M-token window by default, no beta header, with the earlier `context-1m-2025-08-07` beta on Sonnet 4/4.5 retired ([Anthropic context-window docs](https://platform.claude.com/docs/en/build-with-claude/context-windows)); the Gemini line at 1M since Gemini 1.5 Pro — the first 1M window, per the Chroma report — and still 1M in the current flagship ([Gemini model docs](https://ai.google.dev/gemini-api/docs/models): "Gemini 4 Argon ... unified 1M context window"); and Meta's Llama 4 Scout announced at 10M ([Meta blog](https://ai.meta.com/blog/llama-4-multimodal-intelligence), cited by Chroma).

One pricing exception survives the 1M default: Claude Haiku 5.5 bills prompts over 100,000 tokens at a higher rate ($0.50/MTok base input versus $0.10 for shorter prompts, per the same context-window and pricing docs), so "standard pricing at 1M" is a generalization with one named exception.

The caching side. OpenAI's cached input for GPT-5.1 is $0.125/MTok against $1.25 uncached — a 10x spread, matching the economics Manus built on. Anthropic's multipliers: 5-minute cache writes at 1.25x base input, 1-hour writes at 2x, cache reads at 0.1x base (2.5% on Fable/Mythos 5.1, 5% on Opus/Sonnet 5.5) ([prompt caching docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). The mechanics are prefix-hash writes at explicit breakpoints with a 20-block lookback; a timestamp in the prefix breaks the hash exactly as Manus warned. Prompt caching changes the price of retained context, not whether it counts toward the window — Anthropic's docs state this directly.

What breaks first: context rot. The [Chroma technical report](https://research.trychroma.com/context-rot) (Hong, Troynikov, Huber; Jul 14, 2025) evaluated 18 LLMs including GPT-4.1, Claude 4, Gemini 2.5, and Qwen3 under controlled tasks that hold complexity constant while varying only input length ([code](https://github.com/chroma-core/context-rot)). Findings: performance degrades with input length even on simple tasks; degradation accelerates when needle-question similarity is low (semantic matching); distractor impact is non-uniform and grows with length, including on current state-of-the-art models; haystack structure (coherent versus shuffled) consistently affects processing. The report's premise is that Needle-in-a-Haystack measures lexical retrieval and overestimates long-context reliability; NoLiMa, AbsenceBench, and MRCR are cited as prior variants that probe the gap. Anthropic's own docs adopt the term: "As token count grows, accuracy and recall degrade, a phenomenon known as context rot" ([context-window docs](https://platform.claude.com/docs/en/build-with-claude/context-windows)).

The family's own papers supply the economics corollary: on LOCOMO, both the Mem0 and MemOS papers' full-context baselines scored at or near the top on accuracy while paying 9.9–17.1s total p95 latency for roughly 26,000-token histories — on a benchmark small enough to fit a single modern window outright (section 5). The mega-context baseline is accuracy-viable and cost/latency-fragile at conversational scale, and rot-fragile at agentic scale, where the Chroma findings apply to a growing window with no reclamation mechanism. Every other approach in this report is, in this frame, a strategy for keeping the effective window small on top of the same cached infrastructure.

## 7. Newer entries (2025-10 through 2026)

- **Context Folding** ([arXiv:2510.11967](https://arxiv.org/abs/2510.11967), Sun et al., 2025-10-13; [project page](https://context-folding.github.io/)): the agent itself manages working context as a procedural skill — `branch` into a sub-trajectory for a subtask, then `fold` it on completion, collapsing intermediate steps and keeping a concise outcome summary. The when-to-branch and how-to-fold behavior is trained end-to-end with FoldGRPO, reinforcement learning with process rewards for task decomposition and context management. On long-horizon research and SWE tasks the folding agent matches or outperforms ReAct baselines with an active context 10x smaller, and "significantly outperforms models that rely on summarization-based context management." The intermediates of a folded branch never re-enter the main context at all — the same two-plane separation as programmatic tool calling, with the sub-trajectory discipline learned rather than structural.
- **ReFold** ([arXiv:2610.07863](https://arxiv.org/abs/2610.07863), Su et al., 2026-10-06): a training-free rendering layer that "preserves the underlying interaction history while compressing only the model's rendered context." Two removal operators: content an earlier turn already displayed is replaced by a stub, and turns the agent itself reports finished are folded into a one-line note. Removals are strictly reversible — a wrong removal costs one restore from the history. Chunked rendering rewrites the cached prefix only every few steps, containing the cache invalidation ReFold identifies as the cost predictive approaches pay. Reported: token consumption down up to 2.5x, KV memory per session halved, up to 92% of forced compactions avoided under capped budgets, inference accelerated up to 1.7x and costs cut up to 3.4x, across five long-horizon benchmarks and two frontier models. The stated motivation — existing predictive approaches "permanently discard content with no guarantee of recovery" — is the same observation NOOA's design rests on, expressed at the rendering layer.
- **Cloudflare Agent Memory** ([blog](https://blog.cloudflare.com/introducing-agent-memory), 2026-04-17, private beta): a managed memory service with two integration points. At compaction, the harness ships the conversation for ingestion; in the loop, the model gets deliberately constrained tools — remember, recall, forget, list — because "the primary agent should never burn context on storage strategy." The ingestion pipeline is content-addressed (SHA-256 over session, role, and content, truncated to 128 bits, so re-ingestion is idempotent), runs a full pass plus a detail pass for concrete values, verifies each candidate against the source transcript with eight checks, and classifies memories into facts, events, instructions, and tasks; facts and instructions carry normalized topic keys and supersede rather than overwrite, forming version chains. Retrieval fuses five parallel channels — Porter-stemmed full-text, exact fact-key lookup, raw-message search as a safety net, direct vector search, and HyDE vector search — with reciprocal rank fusion, ties broken by recency; temporal arithmetic is deterministic, and the post states plainly that models are unreliable at date math. Benchmarks used: LoCoMo, LongMemEval, BEAM, with an explicit overfitting caveat. The post opens by citing context rot as the reason the "keep everything" and "prune hard" options both fail on 1M windows.
- **The harness/memory ecosystem debate.** LangChain's [Your harness, your memory](https://www.langchain.com/blog/your-harness-your-memory) (Harrison Chase, 2026-04-11), building on Letta CTO Sarah Wooders's "memory isn't a plugin (it's the harness)" argument, holds that context management is the harness's core responsibility and that stateful provider APIs — OpenAI's Responses API, Anthropic's server-side compaction, Claude Managed Agents, Codex's encrypted compaction summaries — place the durable state behind the provider, with model-switching and export consequences. Cloudflare's post takes the managed-service position ("your memories are yours," every memory exportable). The two posts are the clearest published statement that where compaction-free state lives — in your process, in your files, or behind an API — is now a first-class architecture decision, with lock-in as the cost of getting it wrong.

## 8. Relation to NOOA and the sibling harness reports

Against [nooa.md](nooa.md)'s projection-budgeting principle (budget the previews the model sees; keep whole values live in the process; serialize only at the durability boundary), the surveyed approaches sort into four postures.

- **Budget the history** (Manus restorable-compression, Anthropic context editing, Letta buffer eviction). These keep the window as the sole data plane and spend engineering on what to evict and whether eviction is recoverable. NOOA internalizes the same pressure differently: because tool outputs land as live values in the CodeAct session and the transcript carries only bounded event projections, the model-visible surface grows by bounded previews per turn, and the archive paths (provider-error shed, model-callable `collapse` over tagged contiguous ranges) sit dormant. The correspondence is exact in one place: Anthropic's cleared tool result is replaced by placeholder text, as NOOA's evicted context block is marked `EVICTED` in place — and NOOA additionally keeps the collapsed originals addressable by tag.
- **Move the projection out of the window** (memory tool and filesystem, Letta paging, external memory services, Cloudflare). Durable state lives outside the window and re-enters only on demand. NOOA agrees with the "state should outlive the window" premise and disagrees with the transport: its typed fields and memory graph persist by value at the durability boundary, but mid-session state never serializes at all — the execution environment is the second data plane. Where Letta's core memory blocks are bounded in-context text edited by a sleep-time agent, NOOA's dynamic context blocks are expressions re-evaluated over live objects each turn, so the "learned context" is a projection of current state rather than an edited copy.
- **Curate the standing context artifact** (ACE, Manus's todo.md recitation, Anthropic's feature-list plus progress-file harness). These manage the attention-stable top layer: the plan, the playbook, the feature list. NOOA's equivalents are the static prefix (developer-owned, byte-stable) and the memory subsystem's reflection pass, which merges, reconciles, and re-scores records asynchronously — the same shape as Letta's sleep-time agent and Anthropic's Dreams, with ACT-R activation ranking in place of help/harm counts.
- **Spend the native window** (mega-context plus caching; Context Folding's folding agents; ReFold). ReFold is the published closest to NOOA's principle: history preserved verbatim, rendered context compressed, removals reversible, cache invalidation contained by chunked rewrites. NOOA reaches the same invariants by construction (append-only events, tail-only dynamic blocks) rather than by a post-hoc rendering pass, and adds what ReFold does not address — whole values never entering the transcript at all. Context Folding's folded branches correspond to the sub-agent pattern in [fx.md](fx.md) and to programmatic tool calling: bulk work isolated, a summary returned.

Against the sibling single-harness reports:

- [fx.md](fx.md)'s budgeted-variable pattern budgets tool results as bytes at the boundary (64 KiB model-visible cap, spill to content-addressed handles, `read_tool_result` paging) and compacts by lossy-verbatim reclamation into searchable records. Manus is the published antecedent of the spill half (filesystem as context, restorable compression), and fx's compaction records are Anthropic's note-taking made mechanical. NOOA has no byte budget on values — its displacement boundary is process lifetime, not context pressure — the sharpest divergence among all surveyed harnesses.
- [deepseek-harness.md](deepseek-harness.md)'s two-layer invariant ("model-visible means logged" over an append-only session log, with PTC keeping bulk intermediates out of context) shares NOOA's cache-stability rule (byte-stable PTC SDK sections, tool catalog constant across modes) and its two-plane split. The published approaches with the same shape are Manus's append-only discipline and ReFold's history-versus-rendering split; neither names the log-as-program consequence as directly as dsh does.
- [pi.md](pi.md)'s compaction makes the structural guarantee that a tool result never separates from its call (`isCutPointMessage` rejecting `toolResult`, `compaction.ts:351`). None of the surveyed published approaches states a cut-point invariant; Anthropic's oldest-first clearing has no such rule in its documented behavior, and NOOA sidesteps the problem by collapsing only contiguous tagged ranges after the fact.
- [prime-agent.md](prime-agent.md)'s context-as-queryable-variable kernel is the code-level realization closest to NOOA (bounded result ingress, durable namespace, compaction by removing oversized variables). Among published concepts its ancestors are MemGPT's paged hierarchy and the RLM paper Prime builds on; Mem0/MemOS's latency arguments and Cloudflare's constrained-tool argument all repeat the kernel pattern one layer further out.
- [benchmarks.md](benchmarks.md) documents same-model harness variance in agent benchmarks; it is the interpretive frame for every cross-vendor number in sections 5 and 7 — the harness around the model is the variable, and the memory/harness pairs above were each evaluated by their own builders.

The cross-cutting observation: every surveyed published approach still contains a lossy boundary somewhere — Manus's elided page bodies, Anthropic's cleared results, Letta's evicted buffer, Mem0's extraction generalization, Context Folding's discarded intermediates, ACE's retired playbook items. The designs differ in where they place it: at capture (preview bounding, NOOA/fx/dsh), at history reclamation (pi/fx compaction, Anthropic clearing), at session borders (note files, memory tools), or never (ReFold; and NOOA's previews, which are lossy by bounding but lossless by re-derivation — the model can always re-read the value). NOOA's position remains the distinctive one: the lossy boundary sits where nothing the model needs is lost, because the projection it bounds is re-derivable from the process.

## 9. Open questions and uncertainties

- Manus's post is practitioner narrative: the 100:1 token ratio, the 50-call average, and the Claude pricing example are blog-reported with no published ablations, and the pricing predates current multipliers (section 6).
- The Chroma context-rot report evaluates 18 models of the 2025 generation (GPT-4.1, Claude 4, Gemini 2.5, Qwen3). Whether the late-2026 frontier (Claude Fable/Mythos 5.1, Gemini 4, GPT-5.1-class) has moved the degradation curve is not covered by any public report found; the vendor docs adopt the context-rot premise without publishing their own measurements.
- Cross-vendor memory benchmarks conflict: Mem0's LOCOMO table, Zep's DMR/LongMemEval results, and MemOS's LOCOMO table each rank the competitors differently, and Mem0's paper documents Zep operational delays that Zep's own numbers do not reflect. All family numbers here are vendor-claimed under each vendor's harness.
- The Mem0/MemOS full-context observations (highest accuracy at prohibitive latency on ~26k-token histories) are single-benchmark results on conversational data; no published study measures the accuracy/latency tradeoff of full-context on agentic workloads at 200k–1M-token scales.
- ACE, Context Folding, and ReFold report results from their own benchmark suites; no independent replications were located. ReFold's five-benchmark, two-frontier-model evaluation is the authors'.
- Anthropic's server-side compaction, Managed Agents, and Dreams are beta/research-preview features with documented behavior subject to change; the Dreams model list and 100-session limit are as published in the preview docs.
- Llama 4 Scout's 10M-token window is an announcement claim from Meta; public serving of 10M-token contexts is not evidenced by any source read for this report, and the Chroma report evaluates Llama models only up to an extended 128k.
- Gemini 3 Pro preview is shut down per the model docs; the current 1M claim rests on the Gemini 4 Argon listing. The 2M-token window Gemini 1.5 Pro once offered is not listed for current models on the docs page read.
- Anthropic's context-editing placeholder text is documented only as "placeholder text indicating to Claude that it was removed"; the exact wording, and whether it preserves any schema the model can act on, is not published.
- The LangChain and Cloudflare ecosystem posts are position pieces; the lock-in claims they make about provider APIs (Responses API state, encrypted Codex compaction summaries) are cited from those posts and were not independently verified against OpenAI documentation.
