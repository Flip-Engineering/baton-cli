## Verdict on the prior audit

The audit's mechanical findings survive recheck: (1) Bend2 has no in-process evaluator or runtime module loader — program lane must be out-of-process and self-extension must be declarative data plus repository-act tools (feasibility probes 7/8, capability table rows 12-13); capability records are forgeable so authority lives at the effect boundary; (2) the sketch names one `baton2 protocol` while the REPL/citation substrate lives only on the JS line and the Bend2 line has no seat-side commit lane — §8 as written describes a proposal, not shipped surface; (3) fork triple is a proposal over baton's three existing mechanisms plus Fork-and-Flush (workspace inherited, no log prefix); (4) NOOA/OpenCode comparison truncated, twelve-hour evidence belongs to writable/summarization postures, +7.7 edit ablation is 2024 GPT-4 Turbo, `harness.change` is invented, catalog-masking misattributes dsh.

## Where the audit is contested (operator requirements win)

- Recorded budgets vs ambient quotas: the audit/redteam replace "no quotas" with a task budget envelope. Operator requirement 5 forbids ambient step/token/time quotas. Position: no ambient caps in a working seat; task-scoped step/token/time parameters may arrive with tasking, are recorded in the log, enforced uniformly, and reported back; per-call timeouts stay tool properties. Anything that parks or caps work without tasking is a design conflict, stated explicitly.
- Manual acknowledgement: any recommendation implying agent-managed action IDs or manual ack commands conflicts with requirement 3 (Baton owns inferable control identity and automatic handling). Verbs stay concise action verbs; receipts are program-owned.
- Knowledge promotion gate: the statistical/review gate is correct as a seat-side proposal but the admit authority is the orchestrator's admit gate under a run lease (Cairn), not a seat decision. Seat emission is settlement-time and rare, never per-turn writes.
- Compaction dormancy: "expected never to fire" is rejected. Position: projection budgets plus mandatory reclaim path with pending-call carry-forward; proactive at 75% window, reactive on provider rejection; no-compaction is a measurement arm.
- Degraded branch load, persistent in-seat self-extension, grant trees/caveats, TLA+ and binary-size gates in milestone 1: cut, per steelman §2.2 and redteam. Keep codec fixtures, fuzz, replay, crash injection, permission-denial fixtures.

## Proposed revision (concrete design-sketch changes)

1. §1: name the target line. JS line = worker-scoped commit admission is an orchestrator-side proposal plus reachable cite/deref half. Bend2 line = no REPL substrate; commit-and-cite is a proposal with an owner. Pick one line before building §8.
2. §2: append durability = O_APPEND + fsync(file) per commit; dir fsync at create/replace/rotate; temp+rename for rotation only; flock single-writer; List<U32> bytes for large frames. Six-signature C effect family named as required host layer.
3. §3: declare cross-turn residency honestly — standing workset + spill handles persist; within-turn bulk lives in program scope; NOOA cross-turn in-process statefulness is out of scope under OS confinement. Restore OpenCode row; mark NOOA figures paper-reported.
4. §4: async stays but gated — explicit pending-operation state machine (pending, running, heartbeat_due, timed_out, cancelled, lost, completed), quiescence as the completion contract, process reaping. Per the Conductor ruling there are no deadlines that enforce: the log records last-activity per operation and silence beyond a task-scoped observation threshold emits a heartbeat notice with no state change; `timed_out`/`lost` are entered only on concrete lifecycle evidence (provider/OS rejection with provenance, disconnect, process exit, external limit) or explicit authorized cancellation; completion is refused while the pending set is non-empty. Heartbeat choices (wait, cancel, collect partial) are observations the model may act on only through explicit authorized cancellation. The wait mechanism is sleep-poll over the durable pending table (`IO.sleep` + re-read; `Chan.recv` has no timeout at Base) with the quantum as a task-scoped observation parameter; a C wait family is a later optimization, not a prerequisite. Provider-contract check (replacement vs second-item on target providers) is a milestone-2 entry gate. Head-of-line cursor carries no enforcement deadline; reorder happens only via explicit cancellation or second-item commit with a typed event.
5. §5: out-of-process program lane — program + byte-stable SDK under session dir, `bend program` as child (60-110 ms trivial, 95 ms with SDK import), stdout/stderr into log, nested calls re-enter over loopback socket through the guarded pipeline, child holds no authority; optional `bend --check-only` gate (0.1-3 s). Per-call process cost and no-run-time-type-check losses stated.
6. §6: replace runtime module loader with (a) declarative tools as data executed by a compile-time-checked dispatcher, (b) repository-act Bend2 tools gated by `bend --check-only`/`--checkup` with law contracts, (c) optional dlopen C-ABI modules. Authority enforced at effect boundary + OS sandbox. Admitted artifacts execute by content address (copy admitted bytes to a CAS path and exec that) or re-digest at spawn with refusal-on-change logged; a declaration digest alone does not pin executed bytes (S4). Model proposes; orchestrator-side admission installs. Promotion only through the evaluation gate.
7. §7: fork only at completed turn boundaries; settle/cancel pending ops first; refuse harness-state mismatch (no degraded mode); workspace checkpoint as separate bounded mechanism; triple restated as proposed extension to baton's branching record.
8. §8: reachable order — version-pinned cite + deref receipt with bounded render first; seat-side commit admission only if the orchestrator change is taken. Grants start at one orchestrator-minted read grant per citation per reader. Commit cadence stated before grant machinery. Citations machine-checked for claimed hand-off artifacts; inline + re-derivation baselines kept for the E1 experiment.
9. §9-10: workset commits at the same turn boundary any bounding/compaction event consumes (write-before-loss); enforcement section names sandbox profile, approval arbiter, authority snapshot, intent journal, write fences, nested-call handling, crash windows, torn-tail and child cleanup.
10. §11-13: fix recorded-parameters bullet to task-scoped recorded envelope; narrow switches to async-vs-blocking and citation-vs-inline; protocol state machine + property tests now, model checking after stabilization; drop binary-size/startup gates to a spawn smoke budget. Knowledge: the Bend2 SQLite store stays the standing store but relation lineage is currently rewritable by any session that learns an id (`knowledge.bend` relation `ON CONFLICT DO UPDATE` + caller-preserved link ids at `agent-native.bend:215`), violating requirement 6 until hardened. ## Alternative designs (for critique)

### Alternative A — crash-safe blocking seat, no async/program/cite in v1

Build: durable log + turn loop + bash/read/edit/inbox tools, all blocking; O_APPEND + fsync; flock; codec fixtures/fuzz/crash injection; Baton task/report round trip; task-scoped recorded budgets. Defer async layer, program lane, self-extension, fork triple, grants, emulation switches to measured follow-ups.
Benefits: smallest fault surface; proves the seat can run a Baton task safely first. Dependencies: durability C family + provider TLS client only. Costs: forfeits wall-clock overlap and compile-after-five economy in v1. Migration: async/program/cite add as gated layers without log rewrite. Failure boundary: long tools block the turn; steering waits. Falsification: if the blocking seat's turns/task or wall-clock on the fixed task set already matches the async posture within noise, the async layer is not worth its complexity.

### Alternative B — orchestrator-admitted ephemeral programs, no durable self-extension

Build: Alternative A plus ephemeral generated programs only (out-of-process, same sandbox/caps/approvals/logging as shipped executor); model may propose modules, only the orchestrator admits durable tools after review or statistical gate; declarative-tool dispatcher for compiled-after-five patterns; cite/deref-read half without seat-side commits.
Benefits: keeps the compilation economy without a model-controlled durable executor; satisfies the four authorization properties via process separation + externalized signed admission evidence. Dependencies: loopback re-entry protocol + `bend --check-only` admission gate. Costs: per-call process latency; proposal review latency. Migration: durable in-seat extension remains permanently out; promotion path is orchestrator-owned. Failure boundary: admission backlog stalls capability growth; unsigned in-seat evidence is refused. Falsification: if ephemeral programs show no turn/token win over discrete calls on batch tasks, or if orchestrator review latency dominates, the lane is cut back to discrete calls.
